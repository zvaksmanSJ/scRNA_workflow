# ResolveOME single-cell RNA workflow: methods and execution guide

## Purpose and scope

This repository contains source code, workflow definitions, setup recipes,
tests, and documentation for a paired-end bulk-style RNA-seq workflow applied
to single-cell-derived samples. It is designed to preserve the established
BaseJumper RNA methods while adding explicit input/output audits, orchestration,
and optional descriptive analyses.

This is a research workflow, not a clinical assay. It does not make clinical
diagnoses, identify variants, or provide validated clinical fusion or splicing
calls. Matched RNA-DNA identity analysis and DNA-assisted interpretation are
deferred.

## Workflow choices

### Cromwell/LSF route

[`main.wdl`](./main.wdl) is the general-purpose workflow entry point. It
orchestrates BaseJumper-backed stages through audit-gated WDL tasks:

1. Validate the sample sheet, references, runtime, and a new results tree.
2. Run the approximately two-million-individual-read QC branch (about one
   million paired-end pairs).
3. Audit QC preprocessing, alignment, counts, matrices, and reports.
4. Start the independent full-depth branch only after the QC gates pass.
5. Scatter Salmon quantification by sample, audit its outputs, then run the
   final descriptive analyses and results organizer.

The scientific BaseJumper stages remain Nextflow tasks behind adapters. This
is not a tool-by-tool WDL rewrite. Obtain the BaseJumper source separately
through an authorized route and provide it explicitly; this repository does
not redistribute that source.

The WDL requires Cromwell, Java, and an LSF configuration suitable for the
target cluster. See [`wdl/README.md`](./wdl/README.md) for run preparation,
input JSON generation, backend settings, and audit gates. Never reuse an
existing output directory.

### Sprocket-native prototype

[`sprocket/main.wdl`](./sprocket/main.wdl) is a separate direct-tool WDL
prototype for Sprocket's LSF/Apptainer backend. It does not invoke Nextflow or
Cromwell. It is not yet output-equivalent to the BaseJumper workflow and has
not been production-run. See [`sprocket/README.md`](./sprocket/README.md) for
its current limits and validation requirements.

## Inputs and reference data

Use a tab-separated sample sheet with exactly these columns:

```text
sample_id    r1    r2    group
```

Each row represents one sample and its paired FASTQ files. IDs must be unique,
safe for use in paths and commands, and must not contain private or
identifying information. Use absolute FASTQ paths at run time. A generic
template is provided in
[`examples/rna_cells.example.tsv`](./examples/rna_cells.example.tsv).

The setup scripts can provision the software environment and download
checksum-verified Reactome and public Ensembl 104/GRCh38 resources. The
operator must review reference terms and
validate the built indexes for their use case. Additional cohort-specific
resources, such as an Arriba blacklist and fusion annotations, must be
obtained separately and supplied explicitly.

## Core methods

| Stage | Method and intent |
|---|---|
| Read-depth QC | SeqKit probabilistic sampling targets 2,000,000 individual reads using seed `12345`; for paired-end data this is approximately 1,000,000 pairs. |
| Preprocessing | Paired-end fastp adapter detection/trimming and FastQC reporting. No duplicate removal is performed. |
| Alignment | STAR two-pass mapping with the established RNA settings, followed by coordinate sorting and indexing. |
| BAM filtering | Secondary alignments are removed; supplementary records are retained. |
| Gene counts | HTSeq uses positional BAM input, unstranded mode, exon features, `gene_id`, union mode, and ignores secondary alignments. |
| Alignment QC | Qualimap, Picard RNA metrics, flagstat, and RSeQC gene-body coverage are retained as separate evidence sources. |
| Expression | Full-depth Salmon quantification is scattered per sample and gathered only after the upstream audit gates pass. |
| Cohort reporting | Audited gene and transcript summaries, figures, pathway/junction summaries, and a tabbed dashboard are generated by the downstream analysis tools. |

BaseJumper QC score and per-metric criteria are documented in
[`README_WORKFLOW_COMPONENTS_AND_QC.md`](./README_WORKFLOW_COMPONENTS_AND_QC.md).
In brief, the original score uses strict thresholds for mappability, exonic
proportion, intergenic proportion, mitochondrial assigned-count fraction, and
detected protein-coding genes. The source's exonic denominator and Qualimap's
regional percentages are not interchangeable.

## Optional RNA-only research analyses

[`extra_methods/run_rna_research_addons.py`](./extra_methods/run_rna_research_addons.py)
is separately gated from the standard workflow. It can plan or run expanded
QC, positional duplication summaries, DEXSeq exon-bin counts, descriptive
SUPPA2 event PSI, and an independent STAR/Arriba fusion branch. These outputs
are descriptive research candidates only. They do not change the canonical
expression BAMs or BaseJumper QC outputs.

The add-on implementation has not been validated against a cohort or synthetic
fusion/splicing controls. It is sequential rather than a scatter-based
Sprocket/WDL stage. No RNA variant caller is included. Do not use the results
for clinical decisions.

## Software setup

On Linux with conda or mamba installed:

```bash
bash setup/setup.sh --skip-references
```

To also download public references and build the STAR and Salmon indexes:

```bash
bash setup/setup.sh --threads 8 --memory-mb 64000
```

The reference build requires substantial disk space and at least 48 GB RAM
(64 GB recommended). Cromwell, Java, LSF, and Sprocket are separate runtime
prerequisites. Setup details and resource requirements are in
[`setup/README.md`](./setup/README.md).

## Audits, outputs, and safe operation

Input utilities validate sample identity, FASTQ pairing, gzip integrity, and
merge provenance. WDL stage audits gate dependent work; successful submission
or process exit alone is not an audit pass. Keep raw inputs read-only and write
each run to a new, isolated results directory. Preserve logs, metadata,
reports, and checksums for review. Do not point a launcher at existing results
or rerun a completed cohort merely to test the workflow.

The `tests/` directory contains unit tests and opt-in smoke tests. Reference
builds, LSF execution, cohort runs, and research add-ons require their own
runtime-specific validation.

## Release and validation status

This repository is source-only. It excludes cohort FASTQs and manifests,
results, local audit/job records, reference indexes, installed environments,
downloaded assets, institutional logos, backup copies, and the private
BaseJumper source. No project-level open-source license has been selected.
Repository access is private; do not redistribute the code or associated
research data beyond approved collaborators.

Static WDL validation and focused code tests do not certify a clean-checkout
run, a new reference build, or execution on an LSF cluster. The complete
workflow still requires a clean environment setup, end-to-end cluster
validation, and review of generated artifacts before production use.
